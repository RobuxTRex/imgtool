# imgtool
This is a CLI tool designed to help me with formatting a boot medium for testing my OS bootloader and kernel. It is designed for compatibility with other bootloader designs as well, so you are free to use it for your own means (that is, if you are able to).

In essence, the tool acts as an "installer" of sorts. A configuration file is generated by `imgtool setup`, and contains key values that can be tweaked.

This will write - if not already present - an ESP (if the target is UEFI), GPT/MBR, the bootloader to the BIOS boot partition (if the target is BIOS), and generate a basic filesystem with kernel files written. If applicable, the tool will then insert the created partitions to the GPT/MBR, and the bootloader's EFI file to the ESP.

## Usage
The command requires the presence of an `image.toml` configuration file in the directory that you execute it. You can generate this explicitly using the `setup` subcommand; this is not performed implicitly to avoid unintentionally writing a config.

When applicable, the command creates a new image, and constructs a GPT/MBR, ESP, and basic FAT filesystem. The bootloader provided is written to a special BIOS boot partion, similarly to GRUB, with a GUID of `21686148-6449-6E6F-744E-656564454649`. There is no filesystem present, and the partition has a capacity of around 4MiB by default.

## Technical Details
You must declare whether the target system is UEFI or BIOS, and, if using BIOS, whether to use MBR or GPT. GPT is required on UEFI systems.

If you are running a multi-stage bootloader design when targeting BIOS systems, the LBA and sector count of the next stage are written at the following bytes:
```rs
0x01A0 => 0x01A2 (428 => 430) = Sector Size (word, 2 bytes)
0x01A2 => 0x01A3 (430 => 432) = Sector Count (word, 2 bytes)
0x01A4 => 0x01AB (432 => 440) = LBA (qword, 8 bytes)
```

These values are placed directly at the end of the traditional MBR code bootstrap area, and should be used to locate, load, and jump to the next stage of the bootloader. LBA is assumed, however the bootloader may optionally convert the LBA to CHS if unsupported and read using `INT 13h`, `AH = 2h` instead.

Upon reading the next stage, the bootloader should make an attempt to validate the result is accurate by reading the first qword (8 bytes) of the first sector, ensuring it matches the magic byte signature `0x6D656F77205E775E`. The raw binary is aligned to the next sector; the bootloader should jump to `LBA + (SECTOR_SIZE - 8)`.
